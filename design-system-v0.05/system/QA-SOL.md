# Architectural QA — 5 October 2026

Read-only review of the new `system/` entry, inventory, registry, token contract, and the existing integration pages. This file records concrete gaps; it does not certify a release. Review snapshot taken while portal CSS/JS files were still being written.

## Fix first

1. **Arabic font token collision.** [`tokens/tokens.css`](tokens/tokens.css) declares `--gmd-type-ar-body: Amiri, serif` at line 91 and redeclares the same name as `1rem` at line 103. The latter wins, so `font-family: var(--gmd-type-ar-body)` fails. Rename the size variable to `--gmd-type-size-ar-body`, then verify computed Arabic body and heading faces in the portal. The JSON separates `reference.type.arabicBody` and its type scale correctly; CSS parity validation should catch duplicate custom property names.
2. **Component count should stay derived.** [`index.html`](index.html) has 21 `article.component-card` entries and now advertises 21 in the sidebar, hero, filter chip and initial count. `system.js` derives the live filter count. Keep the fixed overview numbers synchronized when adding/removing cards.
3. **Token authority is ambiguous at the new entry.** [`FOUNDATIONS.md`](FOUNDATIONS.md) calls `system/tokens/tokens.json` the new versioned contract and says older `integration/tokens.json` remains authoritative for existing consumers, while the portal's foundation/reference links still send readers to the older JSON. Label both explicitly and link the new contract for new work. A migration table should state which page consumes which layer and how parity is tested.
4. **Broken provenance links.** In [`FOUNDATIONS.md`](FOUNDATIONS.md), links to `integration/tokens.json`, `integration/ui-templates/gmd/premium.css`, and `integration/ui-templates/typography.css` use `../../integration/...`; from `system/`, the correct relative path is `../integration/...`. The v0.01 link using `../../design-system-v0.01/...` is correct.
5. **Field error specimen does not implement its own guidance.** The text field example in [`index.html`](index.html) says errors connect through `aria-describedby`, but its invalid Archive URL input only has `aria-invalid="true"`; the visible error text has no ID. Give helper/error nodes IDs and connect the relevant input to both. The code snippet also points to `name-help` without defining it in the snippet.
6. **Component-token layer is not yet consumed by the primitives.** [`components.css`](components.css) gives `.button` its colors and depth through portal aliases such as `--gmd-ink`, `--gmd-pink`, and `--gmd-edge`; the new `--gmd-component-button-*` bindings in [`tokens/tokens.css`](tokens/tokens.css) are unused. The reference → semantic → component scheme is documented but component-level overrides will not change these actual primitives. Bind the reusable rules to component roles, leaving portal decoration local.
7. **Arabic mode is a bilingual shell, not a translated library.** [`system.js`](system.js) translates major section titles, hero text and some navigation, sets document `lang="ar" dir="rtl"`, and now marks many untranslated reference blocks `lang="en" dir="ltr"`. This is much safer than mislabeling the entire English catalog, but most component specifications/previews remain English. Describe the current scope as a bilingual shell with English reference content, and test mixed-direction reading order before presenting it as complete Arabic documentation.
8. **Combined search and category can hide empty feedback.** `system.js` now keeps Components visible when a search has no text matches. However, `matchedSections` and `totalMatches` are computed from `.searchable` elements before the category filter hides nonmatching component cards. A search matching only cards outside the selected category can produce an empty list without the `#no-results` message. Compute matches after both filters from one result set; component cards are already `.searchable`, so avoid double counting.
9. **Sortable table announces state on the wrong element.** [`components.js`](components.js) sets `aria-sort` on each header button, while the [W3C sortable-table pattern](https://www.w3.org/WAI/ARIA/apg/patterns/table/examples/sortable-table/) places it on the sorted `<th>` with a button inside. Move/remove the attribute on header cells. Sort direction is also a single global toggle, so the first click descends and switching columns inherits the prior column's direction; track sort key and direction together.
10. **Copy toast claims an action that does not occur.** The Toast card's button in `index.html` only has `data-toast="Copied record link to clipboard"`. `components.js` binds real clipboard copying to `#copy-record-link`, but no element has that ID. Wire the button to the copy handler and report failure honestly, or label the button as a simulated toast example.

**Resolved during review:** `system.css` initially contained self-referential `--gmd-font-ui`, `--gmd-font-display`, and spacing aliases. The font aliases now refer to distinct `--gmd-type-*` tokens, and redundant spacing aliases were removed. The earlier zero-result search hid its own feedback; Components is now kept visible for that case. Verify computed fonts in the browser because the separate Arabic-body collision in item 1 remains.

## Release and migration boundaries

- [`INVENTORY.md`](INVENTORY.md), [`registry.json`](registry.json), and [`RESEARCH.md`](RESEARCH.md) correctly distinguish verified artifacts, prototypes, references and legacy studies. They do not claim Radix or shadcn is installed. The portal's broad phrase “Every example on this page works in the browser” should be limited to **native and local demonstrations**; reference specimens and simulated actions are not released package components.
- The existing `integration/tokens.css` still bundles Suisse/FK/Noto roles; current GMD public pages load `ui-templates/typography.css` for Source Sans 3/Source Serif 4/Mada/Amiri/Handjet. The new system token CSS names those fonts but contains no `@font-face`. Every new consumer must load the font-face stylesheet or move declarations into a shared, versioned font layer. Preserve `#FF6183` as action pink: the new JSON/CSS match the shipped palette and intentionally avoid `#FF5B86`.
- The portal's four local CSS/JS files are now present. Source inspection finds native tab arrow/Home/End handling with an RTL branch and a native `showModal()` dialog. These need browser keyboard/focus checks; source inspection alone does not establish assistive-technology behavior. The search, sort and toast issues above are directly visible in code.
- Registry paths resolve locally (31 grouped entries checked); this verifies file references, not behavior, accessibility, source rights or consumer integration. The inventory's documented Pen limit and separate Film/Kayffa/Data adapter gap are appropriate. Add a consumer smoke build and a version/migration note before calling this a product component library.

## External architecture benchmark

[Carbon](https://www.carbondesignsystem.com/getting-started/about-carbon) treats foundations, reusable components, patterns, code and guidance as a shared core extended for specific products. [Spectrum](https://spectrum.adobe.com/foundations/design-data/design-tokens) emphasizes purpose-driven semantic tokens. [shadcn/ui](https://ui.shadcn.com/docs) distributes open component code for local ownership. [Radix](https://www.radix-ui.com/primitives/docs/overview/accessibility) supplies ARIA, keyboard and focus behavior in its actual primitives. These sources support GMD's proposed architecture, but none transfers implementation or accessibility assurance to this static native-HTML portal.
