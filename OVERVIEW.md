# Tavus source audit: overview and QA scope

This workspace records a reference audit of the Tavus marketing site and a signed-in PAL Maker dashboard. The [evidence inventory](evidence/inventory.json) is the route and screenshot index; the [design audit](evidence/DESIGN-AUDIT.md), [component specification](evidence/COMPONENT-SPEC.md), and [motion notes](evidence/MOTION.md) contain the measured details. Captures were made in the user-provided in-app browser. They show a 1026 × 668 CSS-pixel viewport unless a file explicitly proves another size.

Eight existing Pen design frames have also been exported to [HTML and PNG](exports/pen/) for review and later customization. The [Pen export QA](exports/pen/QA.md) verifies their files and packaged resources. They are static visual layers, with no navigation or form behavior and no signed-in dashboard frames.

## What the evidence supports

The public site and dashboard share a brand palette and several typefaces, but use distinct systems. Public pages favor editorial Perfectly Nineties headlines, tiny FK Raster labels, segmented square navigation, cream paper surfaces, black offset shadows, pink calls to action, and full-bleed video or textured imagery. The dashboard has a pale fixed left rail, Suisse Intl interface typography, Berkeley Mono labels, white cards and tables, restrained borders, pink primary actions, and occasional green callouts. These should be implemented as separate marketing and application theme layers over shared brand tokens.

The captured public tokens include paper `#f7f4ef`, near-black ink `#140206`, charcoal `#28292a`, and pink `#ff6183`. The dashboard samples include near-white `#fcfcfc`, muted text `rgb(99, 97, 98)`, pink `rgb(241, 76, 112)`, and tour green `rgb(122, 255, 151)`. These are measured CSS/computed-style values, while any uncaptured responsive rules or media timing remain hypotheses. See [design-tokens.json](evidence/design-tokens.json) and [css-extraction.json](evidence/css-extraction.json) for source-linked declarations.

The public audit covers the homepage, primary product/API/research/vision/pricing pages, selected editorial pages, contact/support pages, and legal pages. The dashboard audit covers the sidebar destinations, resource list and empty states, billing, API keys, support/account overlays, and PAL create, edit, test, and deploy states. Seven public routes—Home, Enterprise, API Platform, Pricing, Research, Vision, and Griffin—also have sequential desktop viewport screenshots through their footers, summarized in [contact sheets](evidence/contact-sheets/). A screenshot at one scroll position establishes that viewport only; the remaining captured routes have opening-view evidence unless their inventory entries list more sections.

The homepage customer-story tabs have captured alternate states for L&D, Healthcare, and Dream Your Own. The selected tab, story copy, portrait/media, and available action change together; these files establish discrete interaction outcomes, while transition timing between states is still unmeasured.

## Coverage limits

- The saved [inventory](evidence/inventory.json) records **29 captured of 246 discovered public same-host paths** and **17 captured of 34 discovered dashboard paths or query variants** at its last generation. Later standalone evidence files add Tools, new Conversation, new Video, and one verified starter-kit detail template; the inventory has not yet been regenerated to count them. Nine other starter-kit detail attempts initially produced blank screenshots, so those blank files are not valid visual evidence. Most uncaptured public paths are individual blog articles, author pages, or categories rather than distinct design templates. The remaining core public solution destination is `/solutions/healthcare`.
- Additional dashboard exploration was stopped at the user's request. `/world`, account authentication routes, and some starter-kit variants remain unverified. The separate [Pen export](exports/pen/) focuses on eight public design frames and does not close these dashboard gaps.
- Desktop coverage is broad but mobile coverage is unverified. The attempted `48-public-home-mobile` capture reports 1026 × 668 and visually matches desktop, so it must not be used as a mobile reference.
- Source screenshots are still frames. The [motion notes](evidence/MOTION.md) separate visible states from CSS-declared keyframes, durations, and transitions. Actual interpolation, scroll triggers, autoplay cadence, and reduced-motion behavior need runtime checks before claiming exact fidelity.
- Dashboard list screens reflect the signed-in workspace's current state, often empty. The audit has not created keys, uploaded files, submitted support, changed billing, or altered account resources. Recreated flows should use local sample data and reversible interactions.
- Public font family names and source URLs are captured, but some public font binary downloads failed. The dashboard bundle includes local Suisse Intl, Berkeley Mono, and Perfectly Nineties files. Verify font loading and distribution rights before shipping fonts with a deployed replica.

## Implementation QA checklist

1. **Navigation and templates:** Every recreated sidebar and main marketing navigation item reaches the intended local route. Reuse one shell per surface. Preserve active item, empty/loading/populated states, and editor Build/Test/Deploy state changes. Represent uncaptured article and starter-kit URLs with clearly scoped templates rather than claiming route-specific source fidelity.
2. **Visual comparison:** At the same 1026 × 668 viewport, compare each implemented route against its same-number source screenshot. Check type hierarchy, sidebar/nav dimensions, content width, card geometry, borders, shadows, image crop, and major color blocks. Compare page sections only against matching scroll-position screenshots.
3. **Tokens and typography:** Inspect computed font family, size, weight, line height, and color on representative headings, labels, body copy, buttons, and cards. Keep public and dashboard token variants explicit; do not silently substitute dashboard pink for marketing pink.
4. **Interactions:** Test keyboard and pointer operation of disclosures, tabs, filters, menus, dialogs, search, create buttons, and editor steps. Verify focus visibility, Escape/close behavior, disabled states, and no unintended navigation or account write.
5. **Motion:** Validate the observed 150–250 ms control transitions and the declared card/button hover treatments. Where source motion has only CSS evidence, label the recreation an approximation. Respect reduced-motion preferences.
6. **Responsive behavior:** Capture real narrow and wide reference viewports before signing off responsive fidelity. Test that navigation, sidebar, cards, tables, dialogs, and media remain usable without horizontal overflow.
7. **Privacy and repeatability:** Keep account names, keys, and support content out of published screenshots and fixtures. Use deterministic sample content so visual checks are repeatable. Source API Keys was an empty state; no key was exposed in its DOM capture.

This overview is an evidence-based boundary for the recreation. A passing local build also needs visual comparisons against the implementation itself; source capture alone cannot certify the finished UI.
