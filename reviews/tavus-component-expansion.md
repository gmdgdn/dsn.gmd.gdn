# Tavus component expansion plan

**Purpose.** Identify the reusable component families visible in the saved Tavus site and dashboard captures, compare them with the current GMD v0.05 integration gallery, and prioritize what a broader component library should specify next. This is a planning matrix; it does not propose copying Tavus layouts or implementing them verbatim.

## Evidence base and limits

The capture inventory records 246 public routes (29 captured, 217 discovered but not captured) and 34 dashboard route/state variants (17 captured, 10 rejected screenshots, 7 discovered but not captured), at a nominal 1026 × 668 desktop viewport. It contains 204 screenshot files, 68 style snapshots, 10 accepted contact sheets, and seven visually reviewed public scroll sweeps. These are route/state counts, not counts of distinct component designs. See [`inventory.json`](../evidence/inventory.json), [`DESIGN-AUDIT.md`](../evidence/DESIGN-AUDIT.md), and [`COMPONENT-SPEC.md`](../evidence/COMPONENT-SPEC.md).

The nine starter-kit detail screenshots listed as rejected are blank white captures; the employee-onboarding example has valid sequential captures. The attempted 390 × 844 public-home capture actually remained 1026 × 668, so it is not mobile evidence. The interviewer and L&D embedded demo panels render blank. Creation dialogs were opened read-only; they do not prove submit, validation, success, or failure behavior. The voices evidence includes both a skeleton/loading state and a populated 75-item table, so these support distinct loading and populated-list specimens. Most captured public routes have only opening viewports; full-scroll evidence is available for Home, Enterprise, API Platform, Pricing, Research, Vision, and Griffin. See the audit coverage section for the authoritative boundaries.

The Pen export manifest describes static generated Tailwind markup and raster renders from a read-only source document. Long page renders reach an 8192-pixel image cap in some exports; use these as layout/reference captures alongside the DOM/style evidence, not as proof of native components, responsive behavior, or interaction logic. Public and dashboard asset harvests also have reported fetch failures (22 and 9 respectively), documented in the audit. The Islamic/Egyptian sources are visual construction studies: consult [`DIRECTION.md`](../design-system-v0.05/direction-review/DIRECTION.md) and [`VISUAL-REVIEW.md`](../design-system-v0.05/deep/VISUAL-REVIEW.md) for verified families and explicit reconstruction caveats.

## Coverage plan

Prioritize by reuse across both editorial and data products:

1. **Core interaction contract:** form fields, select/menu, checkbox/switch, dialog/sheet, inline validation, empty/loading/error/success. These support current GMD controls and several observed dashboard states.
2. **Collection and records:** page header + toolbar, list/table/grid, filters, sort, pagination, row/card actions, selection and media/document card variants. This closes the clearest gap between the current tiny Data demonstration and captured voices/assets/dashboard lists.
3. **Two shells:** public editorial shell (segmented nav, disclosure, hero/section lead, proof/media, footer) and application shell (sidebar, announcement, page header, independent content scroll). Keep them distinct while sharing tokens and low-level controls.
4. **Authoring and configuration:** step-based editor, preview canvas, settings sheet, repeatable form rules, integration/deployment cards. Pattern Studio is a specialized seed, not coverage of these workflows.
5. **Editorial records and commerce:** article/source detail, pricing/usage, FAQ, billing, support/account overlays. Pair reading components with Kayffa references and keep numerical/commerce components straightforward.

For each addition, specify anatomy, content constraints, variants, interactions and focus/keyboard behavior, plus compact/wide and English/Arabic direction behavior. Review against the saved evidence, then adapt its behavior and information hierarchy to GMD’s own composition grammar rather than copying Tavus styling.
